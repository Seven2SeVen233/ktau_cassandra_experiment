# Kendall-Tau Log Reconciliation Experiments

A complete experimental project that validates **Kendall τ distance** as a quality metric for log reconciliation and **Ranked Pairs** as a post-partition log merge algorithm, using real system logs (Loghub BGL/HDFS) on a Cassandra 4.1 cluster.

Corresponding paper: *Kendall Tau Distance as a Quality Metric for Diverged Log Reconciliation*.

Core thesis: when a network partition heals, the divergent operation logs across replicas need reconciliation; the Kendall τ distance (the number of pairwise ordering disagreements between the merged log and each replica's local history) can serve as a unified quality metric across algorithms and decomposes into a "causal component + contested component"; Ranked Pairs approximates the exact Kemeny-optimal merge in polynomial time.

## 2. Environment requirements

| Component | Version | Notes |
|---|---|---|
| Docker | ≥ 24 with Compose v2 | cluster runs in containers |
| Python | ≥ 3.10 (verified on 3.13) | client / algorithms |
| Cassandra image | cassandra:4.1 | built into compose |

**pip installation**

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate    # Linux/macOS
pip install -r requirements.txt
```

**conda installation**

```bash
conda env create -f environment.yml
conda activate ktau-experiments
```

> Note: Python 3.12+ removed `asyncore`, so the cassandra-driver default reactor is unavailable; `scripts/common.py` injects an asyncio shim, no extra handling needed.

## 5. Experiment results

After a full run, `results/` contains all raw data and `results/experiment_report.md` is the auto-generated summary report. Key points:

- **E1 causal decomposition**: Kendall τ decomposes into a causal component and a contested component (Proposition 2); LWW under clock skew produces causal violations that τ counts exactly.
- **E1b counterexample**: the bad order produced by local search is counted deterministically by τ (τ_causal = n_ab).
- **E2 end-to-end comparison**: under high conflict, the τ-optimal merge retains 63.9% information vs LWW 58.1% vs Vector Clock 52.5%, while retaining all operations with higher semantic validity.
- **E3**: Ranked Pairs matches exact Kemeny on M=4..8 (rp_exact rate ≈ 1.0), while Kemeny is an exponential enumeration.
- **E4 real-time monitoring**: during the ordering-drift phase τ̂ rises while maxlag ≡ 0 and Jaccard ≡ 1.0 — τ detects "sub-threshold" ordering divergence invisible to binary lag and operation-set similarity; during partition, τ̂ ≈ 0 while Jaccard drops — the two are complementary.
- **E5**: both τ computation and RP merge are sub-millisecond (M ≤ 100), and merge throughput grows linearly with M.
- **E6a**: under partition asymmetry, RP preserves information retention, outperforming Leader overwrite's loss when the minority is truncated.

## 6. Reproduction and validation

- **Determinism**: all random sources are seed-driven (`model.seed` / `data.seed`); re-running the same configuration reproduces bit-identical results.
- **Self-check**: `python run.py test` runs the smoke tests (τ, RP, Kemeny, scenario generation, baselines, metrics).
- **Data acquisition**: `fetch_trace.py` has built-in multi-source fallback (gitcode raw mirrors, etc.) and format validation; when the network is unreachable, place `BGL_2k.log` / `HDFS_2k.log` manually into `data/`.
- **Platform**: paper Appendix A.1 documents the runtime platform (4-node Cassandra 4.1, single-host Docker Compose deployment, 1 CPU / 1 GB heap per node).

## 7. FAQ

**Q1: Cluster fails to start / port in use**
First check `docker compose logs cass-1`; on a port conflict, change `docker.client_port` in `config.yaml` and re-run `python run.py env && python run.py up`.

**Q2: Data download fails**
`fetch_trace.py` tries multiple mirror sources in turn; if all are unreachable, download `BGL_2k.log` manually from Loghub (<https://github.com/logpai/loghub>) into `data/`; the script validates and skips the download.

**Q3: Python 3.12+ reports cassandra-driver async errors**
`common.py` auto-injects the asyncio reactor shim; no manual setup is needed.

**Q4: Cross-OS compatibility**
All path handling is based on `os.path`; the scripts have no Windows-specific dependencies; `run.py` uses `sys.executable` for cross-platform invocation.

**Q5: How to switch to the HDFS dataset**
Set `data.dataset: HDFS` in `config.yaml`, then run `python run.py fetch`.

**Q6: Run fewer/more experiments**
Core experiments call `run_e1()`–`run_e6a()` in `run_experiments.py` directly; adjust parameters such as `model.trials` / `M`.

## 8. Extending the experiments

- New merge strategy: implement `merge_<name>(scenario, seed) -> (sigma, coverage, unresolved)` in `scripts/baselines.py` and register it in `all_strategies()`.
- New metric: add a function in `scripts/metrics.py` and output it from `evaluate()`.
- More traces: append dataset entries to `SOURCES` in `scripts/fetch_trace.py` (Loghub format).
